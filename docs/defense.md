# Коротко для защиты

**Что такое ELT?** Extract — получить данные, Load — сохранить исходные данные в хранилище, Transform — преобразовать уже загруженные данные.

**Чем отличается от ETL?** В ETL преобразования идут до загрузки в целевое хранилище. Здесь сначала появляются оригинальные JSON.GZ в MinIO, затем Spark читает их через S3A.

**Зачем MinIO?** Это объектное хранилище с S3-совместимым API. Оно отделяет хранение от вычислений Spark, сохраняет RAW и Parquet между перезапусками контейнеров.

**Что такое S3?** Сервис объектного хранения Amazon и распространённый API доступа к объектам. Объект адресуется bucket и ключом. MinIO реализует совместимый интерфейс; это не обычная локальная файловая система.

**Почему исходные файлы сжаты?** Они занимают меньше места и требуют меньше сетевого трафика. Мы сохраняем архивы GH Archive без изменения. Недостаток GZIP — один архив не разбивается на независимые диапазоны для параллельного чтения Spark.

**Зачем Spark?** Он распределяет чтение, преобразования и агрегации между задачами, строит план SQL и поддерживает JSON, Parquet и S3A.

**Почему Transform после Load?** Это условие ELT. Сохранённый RAW позволяет повторить обработку, изменить схему или исправить ошибку без повторного получения источника.

**Что такое Parquet?** Колоночный формат с типами и статистикой блоков. Для запроса можно читать только нужные столбцы, экономя ввод-вывод и разбор данных.

**Зачем Snappy?** Быстрое сжатие и распаковка для аналитики. Максимальная степень сжатия не является главной целью.

**Что такое partitioning?** Разделение данных по значению поля, здесь по дате. Фильтр даты позволяет Spark пропустить неподходящие каталоги. Слишком мелкие разделы создают много файлов и замедляют обработку.

**Чем Spark SQL отличается от обычного SQL?** SQL — язык запросов. Spark SQL — движок, который выполняет этот язык над распределёнными DataFrame и файлами, строит задачи и shuffle. Это не отдельный язык без связи с SQL.

**Как доказать работу?** Показать манифест с объёмом выше порога, RAW в MinIO, активный Worker, Parquet с датами, успешную команду validate, метрики строк, результаты SQL и benchmark с равенством результатов.

**Справедлив ли benchmark?** Данные, очистка и фильтры одинаковы, результаты проверены. Есть прогрев, три замера и медиана. RAW включает повторную очистку, Parquet — заранее подготовлен. Кеш ОС не сбрасывается, поэтому это локальное сравнение тёплых запусков.

**Почему Parquet меньше?** Проверяем фактические числа. Помимо колоночного хранения, мы исключаем большой payload. Нельзя приписывать всю разницу только формату или Snappy.

**Как обрабатываются пропуски и дубликаты?** Обязательны ID события, тип и время. Пользователь и репозиторий могут отсутствовать. Дубликаты удаляются по event_id, их число сохраняется отдельно.

**Команда демонстрации:** `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1`. Быстрый smoke не доказывает соблюдение требования к объёму.
